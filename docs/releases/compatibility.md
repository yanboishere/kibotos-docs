# 兼容策略

本页说明 Kibotos 怎样对外部调用方保持兼容：哪些接口有承诺、不兼容的变化怎样过渡、你的程序该怎样判断服务端提供的是哪一种形态。读者是维护集成代码的开发者。

## 版本号 {#versioning}

- 版本号是 `vMAJOR.MINOR.PATCH`，预发布版本带 `-alpha.N`、`-beta.N` 或 `-rc.N`。
- 兼容承诺从 **v0.1.0** 开始。更早的 `v0.0.x` 是预发布版本，没有兼容承诺。
- 同一个 `MAJOR.MINOR` 的正式版本与 `-rc.N` 版本构成一条**发布线**，例如 v0.3.0、v0.3.1。平台运营方可以在一条发布线内逐台升级服务端，升级期间数据面连接不断开。

## 承诺范围 {#scope}

| 面 | 内容 |
|---|---|
| 控制面 | `kibotos.ctrl.v1`、`kibotos.operator.v1`、`kibotos.enrollment.v1` 的服务、方法、消息、字段语义与错误语义 |
| 数据面 | 会话凭证的取得与使用方式、`/v1/files` 的 HTTP 入口、公开的 WebSocket 流入口，以及 `kibotos.service.v1` 的目标与消息类型 |
| E2B 兼容 API | 官方 E2B SDK 可见的入参、出参与错误码，以兼容目标版本的 SDK 为准 |

不在承诺范围内：

- `kibo` 的参数与输出格式（JSON 输出的 `api_version` 标识它的格式版本）；
- Go 生成代码（`gen/go`）的包路径、函数签名，以及它们依赖的 connect-go 主版本；
- 服务端的部署配置、数据库与发布物命名。

::: tip 用 Go 调用原生 API
从与部署版本一致的 `proto/` 用你自己选定的生成器版本生成客户端代码，不要依赖 `gen/go` 的 Go 签名保持不变。直接导入 `gen/go` 的，把依赖固定到某个版本，升级时按编译结果调整。
:::

## 不兼容变更的过渡窗口 {#transition}

承诺范围内的接口仍可能出现不兼容的变化，但遵守三条规则：

1. **新旧并存一个 MINOR 版本。** 新形态以新增字段、新增方法或新增枚举值表达；被取代的旧形态在引入新形态的版本里继续工作，并标记为 `deprecated`。旧形态最早在下一个 MINOR 版本删除：`vX.Y.0` 引入的替代形态，旧形态最早在 `vX.(Y+1).0` 消失。**PATCH 版本不删除任何东西。**
2. **新形态用新的能力名宣告。** 过渡期内，新旧两个能力名同时出现在 `GetServerInfo` 的能力列表里。
3. **每一处都写进变更记录。** 每个不兼容变化都写在[变更记录](/releases/changelog)对应版本的「升级须知 · 调用方」里：改了什么、旧形态哪个版本删除、调用方要做什么、怎样判断自己是否受影响。删除旧形态的那个版本会再写一次。

## 判断服务端的形态 {#detect}

不要按版本号或 `source_revision` 分支。按下面的方式判断：

1. 调用 `ServerInfoService/GetServerInfo`，取得能力列表。
2. 每个需要特定能力的操作，在列表里按名字**精确匹配**对应的能力名。
3. 缺少能力名时，只让这一个操作失败或走旧路径，不要拒绝整个服务端。

老版本的服务端会静默丢掉它不认识的请求字段。写入新字段（例如 labels、网络策略的 `allow`/`deny`、`egresses`、`resolvers`）之前，先确认对应的能力名存在。能力名清单见[能力名清单](/reference/capabilities)，判断方法见[调用约定](/integrate/native-api/conventions#capabilities)。

## 枚举值的扩展 {#enums}

服务端会在新版本里给已有的枚举增加取值，例如观测类型、失败原因、停止原因。客户端遇到不认识的值时，按最保守的含义处理：当作不可用、有故障或需要等待，不要当作正常值放行，也不要因此拒绝整条消息。

## E2B 兼容的版本 {#e2b}

- 兼容目标固定为官方 JavaScript SDK `e2b@2.49.1`，升级目标版本时会另行说明。
- 已验收的基线是 `e2b@2.46.1`；`2.49.1` 的验收结论尚未取得。只有取得对应版本与能力的执行证据后，才声明已兼容。
- 建议把 SDK 固定到已验收的版本，升级 SDK 前先在测试环境验证。

## 正在过渡中的旧形态 {#deprecations}

| 旧形态 | 新形态 | 旧形态删除于 | 调用方要做什么 |
|---|---|---|---|
| 会话凭证 JWS 头 `alg: Ed25519` | `alg: EdDSA`（RFC 8037） | 最早 v0.4.0 | 把凭证当不透明字符串使用的不受影响；自己解析或校验凭证的，改为接受 `EdDSA` |
| E2B 网关写在资源上的 key 前缀 `e2b.kibotos.io/`、`m.e2b.kibotos.io/` | `e2b.kibotos.app/`、`m.e2b.kibotos.app/` | v0.4.0 起不再读取 | 经原生 API 或 `kibo` 按这些 key 读取、筛选的，改用新前缀 |

已经完成的删除：`NodeResources.ephemeral_disk_bytes` 在 v0.2.0 弃用、v0.3.0 删除。完整记录见[变更记录](/releases/changelog)。
